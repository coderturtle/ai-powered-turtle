# Fictional account-transfer process archaeology

**SYNTHETIC EXERCISE DATA ONLY. Not a real company, customer, operational performance record or compliance model.**

## Case introduction
A fictional transfer team has complaints that some transfers take 12 days although customers expect 2. The first narrative claims missing documents are the cause. The event log supports some rework, but doesn't itself establish the dominant source of elapsed time.

## Demonstration flow
1. Show `initial-brief.md` and `events.csv` (only synthetic records). Ask Mirror for observed/inferred steps and apparent root cause.
2. Show `procedure.md` and `emails.md`; test whether Mirror explicitly distinguishes policy from reality and guesses.
3. **Only after the audience has formed a tentative diagnosis**, reveal `reveal.md`. It shows a fictional approval queue configuration issue and contradicts the easy document-completeness story.
4. Ask Mirror to revise the model and identify the smallest falsifiable experiment. The intended result is a better hypothesis, not guaranteed knowledge.

## Guardrails
Do not describe the event log as valid process-mining data for statistical inference. It is tiny and artificially constructed. Do not give hidden reveal to the model in step 1. If live Copilot is unavailable, use a pre-recorded approved replay or the facilitator's walkthrough. No Strata dependency.
